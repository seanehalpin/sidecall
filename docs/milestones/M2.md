## What was built

| Part | Where | What it does |
|---|---|---|
| Page-side picker | `extension/src/entrypoints/picker.content.ts`, `picker-bridge.content.ts`, `src/lib/picker/` | A MAIN-world `document_start` script on `localhost` and `127.0.0.1`. Hold ⌥ to highlight the element under the cursor with its component name and `file:line`; ⌥-click picks an element, ⌥-drag picks a region, ↑/↓ move to the parent or child, Esc clears. Input is only intercepted while ⌥ is held, so ⌥-click never submits a form, toggles a button or follows a link. |
| Source resolution | `src/lib/picker/frameworks/` | Svelte 5 (`__svelte_meta`), React 18 (`_debugSource`) and React 19 (element stacks mapped through the dev server's source map). All three reach element precision. Includes the React DevTools hook shim and repeat detection. |
| Pick payload | `src/lib/picker/payload.ts` and friends | The full SPEC §5.3 payload: selector and alternates, trimmed outerHTML, curated computed styles, safe-serialised props, component chain, repeat count and instance, recent console errors, page info. |
| Pins and re-anchoring | `src/lib/picker/pins.ts`, `anchor.ts` | Numbered pins that follow scroll and resize. Each pin is re-resolved after DOM changes by source location, then selector, then text fingerprint; stale only if nothing matches. After a full reload the worker restores them. |
| Pick lifecycle and screenshots | `extension/src/entrypoints/background.ts`, `src/lib/picks/` | The worker assigns ids and daemon-clock timestamps, hides the overlay, takes one capture and derives a crop and an outlined viewport image from it, uploads both, and sends `pick.add`. A failed capture or upload never loses the pick. |
| Pick tray and chips | `src/lib/ui/PickTray.svelte`, `Transcript.svelte` | Chips with component, `file:line` and repeat tooltips; hover highlights the pin; click inserts `[n]`; `[n]` in sent messages renders as pills in the transcript. |
| Daemon | `daemon/src/sidecall/picks.py`, `prompts.py`, `session.py` | Pick store, path and column normalisation, a Picks section in each talker turn with crop images, the `get_pick` tool, and task snapshots so the worker gets full payloads and both screenshots per pick. |

## Spec changes (call-outs)

- **§5.1 and §6.9: the pick tray replaces inline composer chips.** A textarea can't hold inline chips, and clicking the page blurs the side panel, so a pick never lands in a focused composer. Picks go to the tray; clicking a chip inserts `[n]`; typing `[n]` works too.
- **§5.3: screenshots come from one capture, with the overlay hidden,** then a crop and an outlined viewport copy (JPEG, not WebP/PNG), so the picker's own pins aren't in the images.
- **§5.2: the nonce is a guard, not a secret** (any script on the page can read it), and input is intercepted only while ⌥ is held.
- **§5.4: React 19 symbolication uses `source-map-js` directly** rather than bippy's `getSource`. Path normalisation, column handling and the "no metadata falls back to the nearest ancestor with precision `component`" rule are now written down.
- **§6.3, §6.5, §6.9:** the Picks format, `get_pick`, crop images, task snapshots and the worker's image caps.
- **§9:** `Task.pickIds` is new; picks are never replied to.

## Two bugs found by running it for real

- **The talker stalled without a page line,** asking the user to describe the page. This came from last turn's page-context prompt, not from the picker, and the older M1 test caught it. Fixed in the prompt.
- **After a denied install, "go ahead" made the talker say it can't run commands** and tell the user to run `pnpm` themselves. Fixed in the prompt. Both are nondeterministic Haiku behaviours, so they can come back: M1 acceptance failed twice before the fixes and passed 14/14 on the run after them. If you see either again, tell me; `talker_model = "sonnet"` in `~/.sidecall/config.toml` follows instructions more reliably.

## Manual verification

Setup: restart the daemon (`cd daemon && uv run sidecall start`), rebuild and reload the extension (`cd extension && pnpm build`, then the reload icon on Sidecall in `chrome://extensions`), and refresh your app's tab. The extension's permissions haven't changed since the page-context update, so Chrome shouldn't prompt again.

1. **Hover.** Open a fixture (`cd fixtures/svelte5-app && pnpm install && pnpm dev`) and hold ⌥ over the page. *Expected:* an outline follows the cursor with a label such as `Card  src/routes/components/Card.svelte:8`. Release ⌥ and the outline disappears. Normal clicking, scrolling and text selection behave as usual.
2. **Pick.** ⌥-click "Project 3". *Expected:* a numbered pin appears on it, and a chip `[1]` appears in the side panel's tray, with a tooltip showing the file, line and "repeated 12×, instance 3".
3. **No side effects.** ⌥-click a "Star" button and "Send invite". *Expected:* nothing happens on the page (no toggle, no submit). Then click "Star" normally: it toggles.
4. **Links.** ⌥-click a link, and an `<a download>` if you have one. *Expected:* the link isn't followed and nothing downloads.
5. **Region.** ⌥-drag across three cards. *Expected:* a rectangle follows the mouse, no text gets selected, and chip `[n]` appears labelled as a region.
6. **Traversal.** Hold ⌥ over a card title and press ↑. *Expected:* the highlight moves to the card header, then the card; ↓ goes back. The page doesn't scroll. (On a Mac keyboard, Option+↑/↓ shouldn't trigger any system shortcut; tell me if it does.)
7. **Esc.** Press Esc with ⌥ released. *Expected:* the current picks and their pins clear.
8. **Chip hover.** Hover a chip in the tray. *Expected:* its pin on the page highlights.
9. **Screenshots look right.** After a pick, check `~/.sidecall/uploads/` (newest files). *Expected:* a small crop of the element with a margin, and a full-view image with the element outlined. Neither shows the numbered pins or highlight box.
10. **Make a change with two picks.** Pick a card title as `[1]` and a sidebar item as `[2]`, then type "make [1] match [2]". *Expected:* the message shows `[1]` and `[2]` as pills, hovering a pill highlights the pin, a task queues, the edit lands in the card component, the page hot-reloads, and the tray empties.
11. **Repeated item.** Pick one card's button and type "make [1] look like a pill". *Expected:* all cards change, since the edit goes into the shared card component. (The fixture files really are edited; undo with `git checkout fixtures/`.)
12. **HMR.** Pick an element, then edit its file in your editor (add a blank line near the top) and save. *Expected:* the pin stays on the same element.
13. **Reload.** Reload the page. *Expected:* pins come back on the same elements within a moment.
14. **React DevTools.** On a React fixture with React Developer Tools installed, ⌥-click a card, then open the ⚛ Components tab. *Expected:* the tree is still populated and picking still works.
15. **Your own project.** Open your `tinotypes2` app, ⌥-click the dropdown you wanted magenta, and type "make [1] magenta too". *Expected:* the agent knows exactly which dropdown, and asks "just this one, or every dropdown?" if it lives in a shared component.
16. **Other tabs.** Open a second tab on a different site, then come back. *Expected:* pins and tray are still there on the original tab.

## Known issues

- **Svelte needs to hydrate first.** Source locations are attached when the page hydrates, so a pick in the first moments of loading has no file or line. The agent falls back to class names and text.
- **A pick's screenshot capture needs the page visible.** Picking while the tab is in the background isn't possible, since ⌥-click needs the page in front anyway.
- **Zoom skews the viewport size** reported with page context (not the picks themselves).
- **React 19 repeat counts can be off right after a hot reload** for elements whose parent is a component (the key comes from transformed-code positions). The next pick is correct.
- **Haiku sometimes leaves `pickId` null in a brief's targets.** The task still gets the right picks, because the turn's picks are always included. For better briefs use `talker_model = "sonnet"` in `~/.sidecall/config.toml`.
- **The daemon's pick store is in memory.** The extension re-sends every live pick when it reconnects, and queued tasks keep their own snapshots, so a restart doesn't lose anything in practice. Old task snapshot folders aren't pruned yet.
- **`get_pick` can't see picks after "Clear all".**
- **Pins draw only in the tab where the pick was made,** plus any other tab on the same origin after a reload or reconnect.
- **The page-side suite doesn't use the real service worker,** and the end-to-end runs use Playwright's Chromium, not branded Chrome. Real-Chrome behaviour of capture timing, ⌥+arrow keys and DevTools coexistence needs your checks above.
- **React DevTools coexistence** is only checked headlessly for the hook itself, not the panel UI.
