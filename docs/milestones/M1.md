# Milestone 1 — Daemon core and text rail

**Status:** built and tested automatically, including an end-to-end run with real Claude. The manual checks in your own Chrome are below.

## What was built

| Part | Where | What it does |
|---|---|---|
| Protocol | `daemon/src/sidecall/protocol/`, `/protocol/sidecall.schema.json` | Pydantic models for every SPEC §9 message, plus pairing, `repo.browse`, `approval.resolved` and ping/pong. Exported to JSON Schema; the extension's TypeScript types are generated from it (`pnpm gen:protocol`). |
| Daemon server | `server.py`, `cli.py` | `sidecall start`: WebSocket on 127.0.0.1:7823. Prints a pairing code, checks the extension Origin and the token, and binds each connection to the repo mapped for the active tab's origin (§9.1). |
| Talker | `talker.py`, `prompts.py` | Read-only Claude session (Read/Grep/Glob only) with `dispatch_task`, `list_tasks`, `get_task_status`, `cancel_task` and `request_undo` tools. Streams replies to the rail and drops narration before file reads. |
| Worker | `worker.py` | Claude Code session under acceptEdits that runs one task at a time from the brief and streams progress events. |
| Permissions | `classifier.py`, `approvals.py` | Pure classifier for SPEC §7 (120 test cases). The PreToolUse hook denies or asks; `can_use_tool` waits on an approval card with no timeout. |
| Queue and state | `queue.py`, `state.py`, `config.py` | FIFO queue persisted per repo; a task that was running goes back to the front on restart. Transcript jsonl, session ids for resume, and `~/.sidecall/config.toml` (or `SIDECALL_HOME`). |
| Extension | `extension/` | WXT + Svelte 5. The service worker owns the WebSocket (JSON ping/pong, backoff, 30 s alarm wake) and tracks the active tab's origin. The side panel has the header, approval cards, a streaming transcript, the task queue (cancel and drag to reorder), the composer, and screens for pairing, repo setup, no local app and daemon offline. Notifications show when the rail is closed. The manifest key is pinned, so the ID is `kcjkimilmanlonlplfancfpoekkphjhb`. |

## Spec changes (call-outs)

- **§9.1 and §9.2 are new.** They cover the connection, pairing, repo binding, turn and task flows, written before the daemon and extension were built in parallel. Choices made there:
  - Default port 7823.
  - Re-sending `hello` on the same socket rebinds the connection to a new repo.
  - A new user turn interrupts the talker's in-flight reply.
  - Denying an approval cancels that step only, not the task.
- **New messages:** `pair.request`/`pair.result`, `repo.browse` and `approval.resolved`, plus extra error codes.
- **§6.3:** the talker drops narration before file reads. A prompt-only rule didn't hold with Haiku. As a result, replies appear a message at a time rather than token by token.
- **§4:** the voice WebRTC connection offers only a loopback (127.0.0.1) ICE candidate. This came from debugging the voice spike in a real browser.
- **§5.6 and §9.1:** notification click behaviour, the extension's own pages keeping the current binding, and `pong` being allowed before `hello`.

## Manual verification

Setup: follow "Run Sidecall" in the README (daemon, extension, pairing). Use the svelte5 fixture or your own app. Claude edits the files in place, so for `fixtures/` inside this repo, undo afterwards with `git checkout fixtures/`.

1. **Extension ID.** In `chrome://extensions`, the ID is `kcjkimilmanlonlplfancfpoekkphjhb`.
2. **Panel opens.** Click the Sidecall icon. *Expected:* the side panel opens and shows the pairing screen.
3. **Pairing.** Enter the code that `sidecall start` printed. *Expected:* the repo setup screen, if your localhost app is the active tab.
4. **Repo mapping.** Click **Choose folder…**. *Expected:* a macOS folder picker opens (it may be behind other windows). Choose the app's folder. *Expected:* the main view, with the repo name in the header and the dot green.
5. **Make a change.** Type "make the heading on the home page red" and press Enter. *Expected:* a one-sentence confirmation with no "Let me check…" narration, then "Task queued", then progress in the task queue, then "Task completed", and the heading turns red on the page without a manual reload.
6. **Approval.** Type "add the zod package". *Expected:* an approval card showing a `pnpm add zod` command. Click **Deny**. *Expected:* the card disappears and nothing is installed. Ask again and click **Approve**. *Expected:* zod lands in `package.json`.
7. **Push.** Type "commit and push". *Expected:* no push happens; the agent or a task result says pushing isn't allowed.
8. **Notification.** Close the side panel and ask for another small change before closing it (or queue one and close the panel). *Expected:* a Chrome notification when it finishes. Clicking it opens the panel, or at least focuses the window.
9. **Restart.** Stop the daemon (Ctrl+C) and wait 30 s. *Expected:* the dot goes grey. Start it again. *Expected:* the dot turns green within about 30 s, and the task list is still there.
10. **Tab switching.** Switch to a non-localhost tab. *Expected:* "No local app". Switch back. *Expected:* the repo view returns.
11. **Dark mode.** Switch macOS to dark mode. *Expected:* the panel is readable.

## Known issues

- **Replies appear a message at a time**, not token by token, because of the narration filter. Revisit in M3 if it hurts voice latency (TTS is sentence-based anyway).
- **The talker connects on its first turn.** That adds a 1–3 s cold start to the first message after the daemon starts, with no pre-warming yet.
- **Haiku's judgement is mixed.** In one run it answered a push request with a line about the previous task. For better briefs, set `talker_model = "sonnet"` in `~/.sidecall/config.toml`, at about twice the latency.
- **`sidecall pair` doesn't exist yet.** Restart the daemon to get a new code. The full CLI is Milestone 4.
- **Undo** queues a task asking the worker to undo its last change; there's no git-level undo.
- **The osascript folder picker** can open behind other windows.
- **The settings preset UI** isn't built (Milestone 4). The classifier already supports all three presets.
- **Restoring rail state after a service worker restart** isn't covered by an automated test.
